# Reduction graph ownership and limits

Linnet owns graph ordering for caller-supplied reduction tables. `Reduction::expand_many` constructs one sparse native `Forest<Integral, ChildVecStore<()>>` graph per call, obtains dependency order through native strongly connected components, and shares exact intermediate expansions across the requested roots. It rejects only reachable cycles, validates every leaf against explicitly declared residuals before cancellation, and releases intermediate coefficient maps after their last parent. Flat rows and direct residual identities avoid graph construction. Because `Reduction` exposes mutable fields, graph state is never cached across calls.

The standalone tests cover a 30,000-node chain, a shared 100-level diamond with coefficient `2^100`, duplicate roots, zero identities, unreachable cycles, zero-weight cycles and missing leaves, nontriangular rows, rule mutation, rational normalization and chained tadpole IBPs. The latter produces the same derivative-closed basis, target reductions, differential matrix, nonzero guards and physical cache identity as the archived recursive implementation. Native Laporta search, row budgets, the 12-slot dispatch limits and the sibling RustRed checkout remain untouched.

The native hot-path planner needs different performance treatment. A structural probe of a genuine paper checkpoint counted 40,840 rules, 74,235 nodes and 515,549 dependencies. Default Linnet bitset-per-node storage retained approximately 9.14 GiB and took 15.662 seconds for graph/SCC construction. The existing sparse native forest reduced retained process RSS to about 262 MiB; graph construction took 0.511 seconds and SCC/indexing 1.060 seconds. Reused plans took 0.167–0.199 seconds, compared with the current DFS planner's 0.176–0.221 seconds. All five tested sector thresholds produced identical reachable and retained node sets and valid dependency order. The sparse experiment completed under a 4 GiB RSS/address-space cap.

These single-run structural measurements do not justify rebuilding a native graph after every small identity update. Keep the existing native frontier planner until graph epochs or rooted owner traversal amortize setup. Substituting an owner API must retain practical memory and runtime, and graph leaves must never become masters merely because a finite search stopped.
