The native terminal check occurs after occupation validation and exact required-cut/support zeros, and before rule scanning. It does not modify the rule list, index order, specialized coefficients, zero domains, or conditions of any rule actually applied. The pending queue uses the same common native order independently of terminal membership.

Both a terminal result and a NoApplicableRule leaf accumulate their exact coefficient with the same native `accumulate` routine. The only container difference is final `terms` versus the temporary `uncovered` map. Exact zero cancellation is retained in either map. Explicit terminals cannot suppress cancellation between identical leaf labels. The RustFlow actual-sum wrapper also combines coefficients across the same input components in provisional and final modes; it applies native reduction independently to each component in both modes.

If a chosen terminal has a valid applicable rule, binding it intentionally truncates that path and may avoid conditions belonging only to the unused rule. If it has a non-NoRule failure, stopping there could hide that failure unless the caller previously proved admission/coverage; the active closure audit does not promote such failures. If it is already NoApplicableRule under the same empty-terminal program, binding it leaves the entire recursive branch structure and coefficients unchanged. The one work-limit distinction is that explicitly declared terminals can still be collected after the application cap, whereas an ordinary NoRule leaf would be reported as WorkLimit. This diagnostic's completed native control is well below its 100,000 application cap.
