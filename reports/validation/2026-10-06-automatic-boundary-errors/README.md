# Automatic supplied-error admission

Physical transport now defaults to `boundary_error_strategy="automatic"`: try the existing scalar uncertainty estimate first, then retry only its accuracy rejection with the bounded signed fundamental-matrix proof. Central transport and its independent precision/order refinement run once. Successful scalar admission retains its arithmetic order; explicit `scalar_norm` remains available, and `fundamental_matrix` forces a proof attempt with scalar fallback.

The error/checkpoint candidate is separate from the central solution until accepted. Source uncertainty floors and accuracy caps remain mandatory. Cancellation, invalid inputs, central solver failures and domain rejection retain their typed behavior. An unavailable, inconclusive or over-budget proof retains the original scalar rejection; no failed trajectory inserts cache entries. Diagnostics report a successful automatic retry's scalar reason. No cache identity, persistence, source search or arithmetic-owner implementation is added.

The final frozen source passes 209 tests: 7 proof controls, 190 integration tests across 27 targets, 4 CLI checks and 8 Python/stub checks. The existing long five-point benchmark is ignored by this routine gate and is not counted as passed. Native and Python/stubgen release all-target Clippy with `-D warnings`, and formatting, pass. The Python coverage includes native transport/cache interoperation, endpoint constraints and prescribed paths, in addition to the new default and diagnostic stubs.

A separate executable linked against the frozen pre-change `fa5fe1b` library and the candidate compares successful scalar handling independently of the refactor. Four systems cover exponential evolution, multiple rational charts, coupled components and an epsilon hierarchy. Exact dyadic central values, propagated errors, every inserted cache payload and accuracy caps match byte for byte across 103 output lines. Mathematical cache identities and implementation fingerprints are intentionally not compared as serialized blobs. The final comparison uses matching Python/stubgen feature graphs; the earlier native-versus-host comparison is retained separately.

New controls show actual infinite scalar amplification recovering through finite signed bounds, multi-chart analytic signed mixing with the same central Step events and checked checkpoints as forced proof, genuine exponential instability remaining rejected, optional dimension limits, cancellation during retry, and central failures which never trigger a retry. The signed proof's mathematical and resource contract is unchanged from the preceding milestone.

`report.json` records source/dependency fingerprints and validation counts. `evidence.tar.gz` contains the frozen source, test logs, comparison harness and outputs, compiler/library hashes, build metadata and per-file checksums. Development failures were confined to test formatting (`PhysicalResult` has no `Debug`) and the standalone compiler harness initially missing the `CARGO_CRATE_NAME` environment variable; both are preserved. The historical c340 signed-proof archive remains unchanged. This milestone uses official Symbolica community `6defcca9` and HEPKit `b96600b0` throughout its new runtime gates.

The signed proof still admits only bounded ordinary rational systems. Sparse epsilon hierarchies, registered-root proofs, authenticated finite-epsilon boundary/sample records and error-aware Laurent fitting remain separate work. No performance or full AMFlow/DiffExp parity claim is made.

An independent read-only review found no actionable issue in the retry orchestration, source evidence caps, cancellation or cache transaction. The reviewer also checked the frozen archive hash, all 314 archived source files against the worktree, and the exact baseline/candidate comparison outputs; it did not run another build.
