This is a read-only semantic/performance design. It does not attribute the current long final phase to a particular operation, change a source, skip proof replay, or modify the verified-reuse integration. Its `active.rs` must remain byte-identical in that integration.

The current active owner first discovers a reachable derivative-closed frontier. It then calls `with_terminals_replayed` on the complete final native program, recomputes every original weighted target, and recomputes every final-basis derivative against that one program. Only after those mandatory checks pass does `reduction/active.rs:389` iterate over the entire historical request set, reducing each label separately to populate `ReducedSystem.candidates`. Individually unresolved historical rows are retired rather than made closure obligations. This loop also collects any conditions encountered by those optional applications and may be costly. The final closed checkpoint is not written until the history loop finishes. A contracting frontier or a progress event with no new derivatives does not prove which of replay, required application, or historical collection is currently consuming time.

The finite-density numerical path does not need the entire historical map. `ConnectionTransport` consumes the basis, differential matrix, target maps and nonzero conditions. Its boundary callback evaluates the declared basis. `PreparedOccupiedFlow::prepare` additionally audits any retained candidate keys and values against its massless physical-label evidence, but it can audit an empty or partial candidate pool without changing the independently audited basis, original input targets or required target weights. `PreparedOccupiedFlow::reduced` exposes the map publicly, so any limited policy must describe its coverage explicitly.

This observation is specific to that active finite-density path. The ordinary physical-family constructor reads candidate maps to build additional physical-coordinate derivative matrices (`physical_family.rs:134`). Optional basis refinement uses the pool to select basis swaps and reports factorization relative to it (`refine.rs:92`). Ordinary caches serialize candidate maps, and supplied-system identities include them. These producers and contracts must remain unchanged. In particular, an empty optional pool must not be advertised as proof that all historical integrals reduce or that an exhaustive factorization search succeeded.

A minimal future option could be `HistoricalCandidateCollection::{All,None,AtMost(n)}`, accepted only with active-target closure. Initially preserve All as the existing default. Select any bounded prefix deterministically from the already saved ordered history; do not change discovery, rule precedence, source equations, terminal basis, or the mandatory final audit. None means no additional individual history application, not zero values for those labels. AtMost bounds the number of optional applications; the existing per-application work limits remain in force. A label-count cap alone is not a wall-time guarantee. Never install an uncertified identity for a weighted-target summand merely because uncovered contributions canceled in the complete weighted target.

Keep the same accumulated nonzero-condition map throughout discovery and the mandatory final audits. Skipping optional history must not drop any guard already encountered in those phases, including guards from earlier retired paths. If an optional application is executed, retain its actual conditions even when it is individually unresolved, matching current behavior. Exhaustive collection may add conditions that limited collection never encounters; that difference is legitimate only for unused map applications and must be recorded honestly. It is not an excuse to prune preexisting conditions or weaken a required target/derivative guard. Cancellation and fatal native errors encountered by executed work retain their failure semantics. Native NoRule, ConditionVanished and work failures in optional history are reported as assessed failures exactly, never as successful maps.

Diagnostics must distinguish historical labels, requested optional labels, assessed labels, certified maps, assessed unresolved labels, and uncollected labels. Existing `retired_unresolved` cannot include unvisited labels. Save the uncollected list or an exact count/hash plus a bound ordered history/selection rule. Every such record says `history_is_coverage_certificate=false`; uncollected means not assessed, not zero, reduced, certified, or unresolved. The closed connection claim remains exactly the complete original-target/final-basis-derivative claim. Include the collection option in configuration/provenance and any cache identity that exports candidate maps.

Measure before promotion. Add phase timings/counters for final full replay, required target applications, required derivative applications, historical map applications, physical-label audit and checkpoint encoding. For a completed immutable checkpoint, a separately bound diagnostic can compare All with None or a cap using the same full replayed final program, frontier and original targets; preserve final bytes and guards. A live progress timestamp alone cannot distinguish the cost of thousands of optional applications from replaying tens of thousands of proofs. No timing claim is made here.

Required regressions for a later independent source batch:

- All versus None/AtMost yields identical final basis, matrix, weighted target maps and final native program bytes, with every mandatory application executed in both modes.
- A failure in mandatory replay, any original target or any basis derivative remains a failure irrespective of collection policy. The optional path cannot publish a closed checkpoint first and revise it later.
- Required weighted-sum cancellation does not manufacture maps for its individually uncovered summands. Uncollected and assessed-unresolved counts/lists are distinct and exactly partition history with the certified pool.
- Every condition present before optional collection remains afterward. Conditions generated by executed failed optional applications are retained. Additional exhaustive-only conditions are attributed, not silently normalized away.
- Cancellation, per-application limits, a zero optional cap, deterministic prefix order and malformed configuration fail or stop according to the documented scope.
- Physical-label audit covers every retained candidate as well as all required basis/target labels; omitted historical labels grant no new physical admission.
- Ordinary physical-family, basis-refinement and cache behavior remain unchanged. Existing candidate completeness tests on those paths are not weakened.

The change is semantically feasible for finite-density active closure, but remains unimplemented and unmeasured. It must be a separate reviewed change after the verified-program reuse baseline, not combined with that trust-preserving optimization.
