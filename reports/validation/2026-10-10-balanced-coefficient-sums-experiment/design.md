This isolated experiment changes only the parenthesization of exact rational additions feeding one descending pending label. Native source discovery, proof replay, rule order, guard application and zero semantics are unchanged. The source program remains immutable. It is not a new elimination backend or a numerical approximation.

Each pending map entry stores at most 32 rational coefficients. Reaching 32 combines that buffer with a deterministic pairwise balanced tree and keeps at most one nonzero result. On pop, the complete coefficient is balanced and normalized before the work-limit, terminal, zero, occupation or rule checks. A zero sum is discarded without applying its unused rule. Previously applied rule conditions remain in the result even if their output later cancels. Terminal and NoApplicableRule output accumulation remains the ordinary native exact routine. Other failures remain separate, exactly as in native reduction.

The key-capacity rule needs care. Buffered zero sums may leave dead keys that eager normalization would already have removed. Before rejecting a new key at pending capacity, normalize all pending sums and remove exact zeros, then apply the unchanged native distinct-key capacity decision. A known existing key can accept an additional contribution: the buffered map never exceeds the native key bound, so reviving an undetected dead key cannot create an extra key beyond that bound. Before returning pending WorkLimit records, normalize every buffered entry and remove zeros. The current popped coefficient is already normalized. An explicitly returned excess weighted RHS still remains a WorkLimit failure and is never later merged away.

A fixed 32-coefficient buffer limits extra storage to 32 rational objects per admitted pending key, plus the existing current application output. This does not create a new application or key-budget exception. Polynomial coefficient size remains subject to the existing exact algebra implementation, as in the baseline. The standalone driver propagates native errors fatally and adds no ad-hoc zero, condition simplification or hidden fallback. Native normalizer errors must also remain fatal in any later library implementation.

The highest-first common native order guarantees every admitted RHS is lower than its parent. Thus all ordinary incoming paths to a supported label have been considered when that label is popped. Changing the addition tree preserves its exact coefficient and the rule selected at that point. Invalid/unsupported powers retain the native total-order fallback and failure behavior; the experiment does not use descent to excuse those cases.

Generic controls use fresh public native discovery and full program replay from explicit source rows, not hand-installed rules. They compare all output coefficients, ordered conditions, residual reasons and application counts to native reduction across a grid of application and pending-key budgets. Dedicated controls exercise a canceled key freeing capacity, unused versus already-used guards, full decode replay, buffers 31/32/33 and cross-buffer cancellation, and an explicit coupled-index ConditionVanished. Only after these pass will the actual slow component be timed with no known answer used during reduction; the saved native output is an after-the-fact equality check.
