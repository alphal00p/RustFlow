# Isolated whole-call terminal-promotion cache

Eight small native tests pass. This prototype reuses complete unit reductions only under one owned immutable native program and exact application limits, and then permits one checked kind of terminal transition. It does not cache or substitute descendant tails, import numerical answers, alter native rules, or change production code. There was no full slow-target run or Cargo/shared-target build.

`CachedProgram` privately owns `GuardedProgram`, entries and shape quotas. Call keys include the complete target and both native work limits. Cache insertion occurs only after a successful native call whose residuals are exclusively NoApplicableRule. No WorkLimit, other application failure or arithmetic error is cached. Entries retain their exact coefficients, native residual order, ordered conditions and logical rule-application count. Native errors propagate. Hits clone the complete unit result; the live native queue is never bypassed at an intermediate integral.

Promotion consumes this owner. The new terminal set must contain all old terminals. Each added label must independently return precisely empty, conditionless NoApplicableRule under the old program. The prototype then invokes **with_terminals_replayed**, preserving full independent proof replay and normal terminal validation. Only matching cached NoApplicableRule records are moved to terminal terms. Other residuals and all conditions/counts remain unchanged. The native uncovered map has already combined each label exactly, and no promoted label can previously have been a terminal, so no extra coefficient operation or reordering is needed.

Replacing the program discards all entries. There is no method for injecting an externally computed result or reusing a cache with another source corpus, ordered rule set, variable map, order or terminal set. Persisted native decoding constructs and replays an independent program; the tests compare its fresh reductions with the promoted results. A future library API must preserve this ownership/epoch contract, not replace it with measure-name or bare-pointer equality.

The small fixture gates cover:

- Mixed promoted and still-uncovered leaves, three independent whole-call hits, exact native coefficient/residual comparisons.
- A canceled unused pole versus a retained applied guard, ordered conditions, independent rebind replay and encoded/decoded native reduction.
- NoRule branches that cancel exactly, retaining already-applied guards.
- An application-cap counterexample: the old NoRule leaf fails at the cap, while the same leaf as a terminal succeeds. The failed old result is excluded from the cache and the new call runs natively. A coupled vanished index guard is also excluded and cannot be promoted.
- Ninety combinations of application limits, pending limits and cache capacity; each checks old and promoted results against the unchanged native reducer, including a repeated lookup.
- Rejection of removed terminals, reducible additions, invalid occupation indices and insufficient replay rule budget; preservation of existing terminals during a valid extension.
- Deterministic eviction, changed limits, replacement with a different source/rule result, retained-term and coefficient-bit admission limits.
- Required-cut zero rejection as a terminal and valid caching of the complete exact-zero unit result.

The cache quotas bound entry count, retained polynomial term count and the sum of retained integer coefficient bit sizes. They are accounting limits, not a strict bound on all allocator overhead, native CAS scratch or the memory of the shared immutable program. They apply only to caching; a declined insertion leaves the unchanged native result and future miss behavior. Existing native application/pending budgets remain independent. Production cancellation and storage validation would still need to run at their current owner boundaries.

Fixtures are small actual GuardedSourceSystems. Rules are generated by native discovery and validated by GuardedProgram construction; no hand-installed reduced answer is used. Fixture source patterns came from the frozen balanced-sums experiment, with the initial stopping set intentionally empty for the guarded diamond. The source and all static dependencies are hash-bound by the build/run records. The pinned native library is the verified-program-reuse prototype, SHA 91f0dc1e00677301daf9bb1146fb318f713f6a71a8598534c0d36ca947defd69; the matching Symbolica library is SHA 2d7cc34a7e8c80b7581cb0ab0b20cda4af578569e97f703a2ea498f09eb045af. The standalone wrapper is compiled without modifying either library.

The related read-only assessment found exactly nineteen scheduled final calls that repeat the immediately preceding provisional calls after seven old NoRule leaves become terminals. That establishes a possible integration site, not measured end-to-end savings. The original run timed out without proving all final repeated calls completed. The real 313.8-second component was not rerun here, and no three-loop closure, boundary or period claim follows from these tests.

A production integration would still perform the existing independent full source replay and the unchanged original weighted-target and every-basis-derivative audits. It would supply those audits with maps proved equivalent by the checked transition, preserving all remaining failures and exact conditions. This report is a prototype and proof/test result only; no production promotion is implied.

Independent read-only review found no blocker in the implementation's narrow transform. The reviewer confirmed immutable ownership, exact-limit keys, failure exclusion, old-terminal subset checks, exact old NoRule checks, full replay, and safe aggregate quota accounting. The review explicitly does not justify descendant substitution or reuse across broader program changes.
