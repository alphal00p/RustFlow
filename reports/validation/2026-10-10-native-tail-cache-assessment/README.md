# Exact reduction reuse assessment

Generic substitution of fully reduced unit-coefficient tails is not compatible with the current native reduction contract. The useful narrow candidate is whole-call reuse across the final **NoApplicableRule-to-terminal** transition, with an explicit equivalence check. No production code, native proof, numerical value, or reduction result was changed for this assessment.

The native pending map uses the common, replay-validated IntegralOrder, harder labels first. Every accepted rule strictly descends. Consequently, supported labels receive all incoming contributions before being popped and are normally expanded only once per call. This already prevents repeated recursive expansion inside a call. It does not prevent different root calls from traversing overlapping labels.

A fully reduced tail lacks the cancellation context needed for safe substitution. For example, let A→B−C, B→L, and C→L, with L's rule carrying a nonzero guard x. The normal queue cancels L before application, so it neither acquires x nor reports a vanished guard there. Independently reduced B and C tails can retain x or report a failure that the A reduction never encountered. Already-applied guards, on the other hand, must remain even when their resulting coefficients later cancel. The existing native pending-diamond tests exercise this distinction. Replacing a tail also alters distinct-pending capacity, application accounting, ordering of conditions, and work-limit residuals unless those effects are separately reproduced.

`audit.py` reads existing metadata and the current owner code; it runs no native search, replay or reduction. The nineteen completed provisional rounds contain 302 reconstructed unit calls and **zero duplicate query labels within a round**. All nineteen program digests differ. Initial requests independently identify the three original unit roots, and every derivative component is reconstructed using the saved deformation slots [0,1,2,4] and the exact history/defer checks in active.rs. The FH profile's 42 queries are also all distinct. Thus a cache keyed to the identical immutable program, stopping set and limits has no demonstrated hit opportunity during these active rounds.

The final provisional round is different. All seven frontier labels and all their raw derivatives have completed request history. The target loop therefore executed its three unit calls, and the traversal executed all sixteen derivative component calls before publishing round18. On the successful continuation path, the final-audit target and derivative loops schedule those exact nineteen calls again, in the same order, after terminal rebinding. This is a control-flow comparison, not merely overlap between aggregate sets. The original run timed out without a closed checkpoint: **the evidence does not establish that all nineteen final repeated calls executed or completed**. The separate FH native profile completed each selected unit query, including the expensive raised component at 313.800652 seconds.

The seven added terminals were independently checked by FP: each is exactly `Unresolved(NoApplicableRule)` with no output terms under the empty-terminal program. This supports a narrow reusable-result theorem:

1. Keep precisely the same immutable source context, ordered rules, coefficient-variable map and native order; retain the old terminals and add only labels whose old one-step application is NoApplicableRule. Validate all new terminal roles, zero-domain and storage constraints normally.
2. Retain complete unit-call results under the exact target and the two original application limits. Initially admit only successful calls whose residuals, if any, are NoApplicableRule; exclude work-limit and all other failure records, and never cache arithmetic errors.
3. The added terminal labels stopped without children before, and stop without children after. Every pending insertion, exact cancellation and actual rule application therefore remains identical. Ordered conditions and application counts remain identical. Reclassify only the cached NoApplicableRule coefficients at newly added terminals as terminal terms; retain other NoApplicableRule residuals in their native order.
4. Excluding work-limit results is essential. Native reduction exempts a declared terminal from the application-cap check, while the former nonterminal NoRule label would not have been exempt. A partial result cannot be relabeled using this argument.
5. Perform the existing full independent rule replay before the final audit. Run the unchanged original weighted-target and every-basis-derivative reconstruction/audit with the proven-equivalent unit maps. No residual becomes a master because of a cache hit, and no new source coverage is inferred.

This is whole-call reuse, not memoized descendant replacement. Empty old terminals make the terminal-superset requirement automatic in this particular final transition. The theorem is not a basis for carrying results across newly appended/prepended rules or removed terminals. In particular, new direct-zero rules can supersede the old first applicable rule, and a former NoRule leaf can acquire descendants that change later cancellation.

A scoped cache should own or borrow one immutable program rather than use a globally reusable pointer address. Its key includes target and both limits. Program construction, union, decoding, or ordinary terminal changes invalidate it unless a checked transition such as the one above is performed. Bound entries and retained coefficient/condition storage explicitly, evict deterministically, and fall back to the unchanged native call on a miss. Preserve logical application counts on hits; report physical calls avoided separately. Caller cancellation and storage validation still run. A cache must not omit a guard, reinterpret a failure, or reuse a result under merely the same measure ID.

| Candidate | Contract | Evidence here |
|---|---|---|
| Same-binding complete-call cache | Safe under exact immutable binding and equal limits | No repeated query within the saved active rounds or selected FH profile |
| NoRule-only terminal promotion | Narrow equivalence above; final independent replay retained | Nineteen scheduled repeat calls, seven independently checked NoRule terminals |
| One-step apply cache | Consult only at normal nonzero pop; preserve native status and ordered conditions | Feasible, but native apply accounts for only 14.84 s / 365.48 s (4.06%) of the instrumented slow call; coefficient arithmetic dominates |
| Arbitrary reduced-tail cache | Missing live cancellation/budget context | Counterexample above; not recommended |
| Last isolated pending entry | Potentially safe with extra trace/budget/failure invariants | No saved count or cost evidence; not recommended as a first implementation |

FH saves final maps and counts. FP saves operation totals and overwrites its last-operation progress record. Neither records every visited integral, so expensive descendant overlap across the 42 calls cannot be quantified from these artifacts. Shared final terminals alone do not establish shared expensive tails. No throughput or full-workflow speed estimate follows from the 313.8-second measurement; it only identifies a specific repeated computation that the narrow transition could avoid.

Before any prototype is promoted, test exact ordered conditions and all coefficients against ordinary native replay/reduction for: canceled unused guards versus retained applied guards; an added NoRule terminal versus an actually reducible or condition-failed label; unchanged, removed and added terminal sets; source/order/rule-precedence/variable-map mismatch; cache eviction and both limits; pending-capacity WorkLimit and application-cap WorkLimit; remaining NoRule labels outside the new stopping set; duplicate terminal cancellation; constant/zero results; and persisted decode plus the unchanged weighted final audit. The proposed prototype must not special-case physical topology or substitute numerical epsilon values.

Peer review independently agrees with both the generic tail obstruction and the narrow promotion argument. The immutable result-binding, ordered-condition, failure, budget and final-replay requirements are part of the proposal, not implementation claims. Source digests and all inspected metadata paths are bound in `input-bindings.json`; quantitative observations and exact call sequences are in `observations.json`.
