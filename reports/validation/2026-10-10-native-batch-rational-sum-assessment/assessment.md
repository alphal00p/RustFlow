No existing delayed-normalization batch sum was found in the inspected pinned Coefficient owner. The feasible next design would be a bounded, temporary polynomial accumulator inside the existing exact algebra owner. Current measurements do not establish enough benefit to implement or promote it.

RustRed Coefficient is Symbolica RationalPolynomial<IntegerRing,u16>. Its documented invariant requires a nonzero, normalized denominator coprime to the numerator. RationalPolynomial::Add already uses a denominator GCD and reduced cross-products. With equal denominators it invokes from_num_den(..., true); with unequal denominators it cancels the new numerator against the denominator GCD. Atom-to-rational conversion handles Add with a pairwise fold. Atom::together converts to FactorizedRationalPolynomial; that representation's Add also cancels numerator factors and normalizes after each pair. Neither inspected route provides the requested raw-LCM batch operation. Factorized conversion is an existing alternative representation, but no evidence yet justifies its factorization/conversion cost here.

A two-phase batch could accept at most 32 already canonical coefficients on one exact variable map. Compute L, a denominator LCM, using the existing polynomial GCD and exact-division owners; then compute each exact quotient L/d_i and the polynomial sum N = sum_i n_i*(L/d_i). Only after the complete numerator is formed should from_num_den(N,L,Z,true) create a Coefficient. A second variant could maintain raw polynomial N,D incrementally with g=gcd(D,d), N←N*(d/g)+n*(D/g), D←D*(d/g), postponing only the numerator/denominator cancellation. These variants are alternatives for measurement, not proposed production patches.

The raw pair must have a distinct private type. It must never be passed to Coefficient arithmetic, native guards, persistence, equality checks that assume canonical fractions, or public APIs. In particular, from_num_den(..., false) is not a valid shortcut: the existing API explicitly requires the caller to prove coprimality. A zero raw numerator is an exact zero because every input denominator and L are nonzero formal polynomials; no epsilon or other parameter value is substituted. Nonzero batches require final canonicalization, sign normalization and exact map validation before pop, capacity compaction, WorkLimit output, terminal checks or native apply. Conditions from already applied rules remain untouched even if the coefficient later simplifies or cancels.

The arithmetic reason to consider the design is that it could replace many intermediate numerator GCDs by one final numerator GCD and avoid some repeated numerator rescaling. It does not eliminate denominator GCDs, polynomial products or exact quotients. The present 247-second addition measurement combines all of those costs. It does not show whether numerator GCDs dominate. The eight existing immutable samples are sufficient for a future phase attribution experiment; another expensive integral reduction is not needed merely to test that premise.

Deferring cancellation can cause severe expression growth. A denominator LCM over 32 inputs can have a much larger sparse or dense support than any individual denominator. Early cancellations in the existing eager or balanced order can remove complete denominator factors before unrelated fractions arrive. A batch that waits until the end may retain all those factors. Even exact cancellation of many small groups does not bound the unreduced common denominator if the grouping is missed. The finite input count therefore bounds object count only, not exponent degree, polynomial terms, integer coefficient bits or native GCD scratch space.

A future implementation would need explicit admission before every polynomial GCD, product, quotient and numerator sum: variable-map/ring and denominator validity, u16 exponent envelopes, sparse term-pair/sum work, retained term counts, cumulative batch work and retained-byte estimates. The existing ExactAlgebraLimits/validation helpers provide useful owners and error conventions, but their own documentation says term-pair bounds do not fully bound Symbolica GCD or dense-multiplication scratch space. That limit must stay explicit; a hard total memory claim would require additional CAS support. Unexpected nonexact quotient, arithmetic panic, invalid normalized output or failed map validation is an error, never a zero or successful fallback.

A deterministic optional path can decline before an operation when its conservative batch-growth estimate exceeds its own budget. Keep all original canonical input coefficients intact until commit; on this preflight decline, use the unchanged native summation order on those inputs. No partial result may leak into pending coefficients or conditions. This is distinct from catching an arithmetic failure and silently retrying: actual algebra failures must propagate. Native integral/application budgets, pending-key capacity, exact-zero removal and unresolved record ordering remain the existing owners' responsibility. Any new arithmetic work cap must be separately reported rather than silently changing those budgets.

Before any integration, tests would need exact agreement across the existing 810 budget cases, the same guard/cancellation/WorkLimit controls, generic parameter-dependent denominators, new common-factor cancellation, canonical signs, different coefficient maps, zero and one denominators, 31/32/33 contributions, large shared-factor denominators, intentionally disjoint denominators, ordered cancellation that makes eager arithmetic much smaller, preflight decline with the original-order result, exponent/term/byte limit failures and invalid exact-division handling. Round-trip native coefficient serialization must only see canonical final coefficients.

This assessment adds no code, sample capture, benchmark, slow-target run or production recommendation. The complete generic-epsilon endpoint and all native proof semantics remain unchanged. If later profiling of the eight frozen samples attributes most cost to numerator GCDs and growth estimates remain small, that would be a concrete reason to test a source-copy CAS batch prototype. Current small/mixed balanced and identical-denominator results alone are not that evidence.
