These are fresh matched double-cut partial-placement closure trials, separate from the frozen initial 300-second experiment. They use exactly the same compiled native algorithm, regenerated source presentation, actual target sums, derivative masks and support-proof identity. No historical rules, partial checkpoint or manually supplied master is imported. Only the explicitly recorded bounds change to 24 rounds, 16,384 cumulative requests, frontier 4,096 and 1,200 seconds per arm; the ray/point/depth/rule/direct-zero limits remain unchanged.

The static executable and every runtime-read input were copied and hashed before launch. Shared Cargo outputs may therefore change without affecting either run. The copied build manifest preserves the original compile-time library paths and hashes; those library files are provenance, not runtime dependencies. Each launcher verifies the capsule before and after the process. All target/native source/gap/condition checkpoints are retained.

After both runs complete their post-hash checks, `finalize.py` moves the byte-identical 1.27-GB executable to the stable path recorded by `executable-relocation.json`, outside the repository. The original runtime manifests remain unchanged. `verify.py` resolves that explicit relocation when validating their hashes. To restore the original command paths for a separate reproducer, copy the relocated executable back to `capsule/pilot` and verify its bytes and SHA256; do not rerun into an existing frozen output directory. Native program `.bin` files remain in this report and are distinct from the large static executable.

`summary.json` records the final bounded outcomes. Unclosed, timeout or deferred native work is never reported as a zero/master or numerical prediction. These trials do not establish partial-placement production admission or three-loop numerical acceptance.
